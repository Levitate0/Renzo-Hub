# Deliberate differences — do NOT close these

Re-raising these wastes a future session's time. They are correct as they are.

### Shared paste-a-link helper is trapped in the manga half and cannot parse Renzo's path-shaped invite links
- **area:** Auth flows Hub cannot complete: first-run setup, invite acceptance, password reset (Renzo anime web ↔ Hub anime half)
- **why it is correct:** Lift the helper into hub/core (e.g. `top.levitatemedia.renzo.hub.core.LinkTokens`) as `fun tokenFromLink(pasted: String, queryKeys: List<String>, pathPrefix: String? = null): String` that (a) returns the `key=` query value for any key in `queryKeys`, (b) falls back to the last path segment after `pathPrefix` ("/invite/"), and (c) returns the trimmed input unchanged when neither matches — then have feature-shiori's AuthUi.kt:454-461 delegate to it so both halves share one implementation. The anime reset screen calls it with `queryKeys = listOf("reset", "token")` (the mail link uses `?reset=`), the anime invite screen with `queryKeys = listOf("invite", "token"), pathPrefix = "/invite/"`. Without this, a user who pastes the invite URL the Hub itself copied (AdminScreens.kt:361) into a naive `extractQueryValue` port would submit the whole URL as the token.

### Emailed invite/reset links open a browser, never the Hub (no app-link intent filters)
- **area:** Auth flows Hub cannot complete: first-run setup, invite acceptance, password reset (Renzo anime web ↔ Hub anime half)
- **why it is correct:** None — do not close. A self-hosted server's public URL is user-specific, so App Links (which need a fixed, verifiable domain) cannot work here; the correct native answer is the paste-the-link field the manga half already uses, which the three preceding recommendations adopt. Recorded only so the paste field is understood as deliberate design rather than a shortcut.

### Configuration and wizard routes are unreachable on TV, replaced by the instance's web address
- **area:** First-run Setup Wizard — entirely absent from Hub (Shiori web A vs Hub manga half C1)
- **why it is correct:** No change. This is the deliberate platform decision, and it is also the template the first-run gate should follow on TV (see gap #3 recommendation (a)): route the TV first-run case to TvUseAComputerScreen rather than trying to type a username with a D-pad.

### Mouse paint-drag row selection, edge auto-scroll and Ctrl+A have no Hub equivalent
- **area:** Unknown-source re-matching ("Search match") — Shiori web (A) vs Hub manga half (C1)
- **why it is correct:** Do not close. These are mouse-only affordances (press-and-drag across rows, hover-driven auto-scroll, a Ctrl chord) that have no meaning on a D-pad or a touchscreen. The Hub dialog should reach the same end state through the native idiom already proven on this screen — tap-to-toggle plus All / None / In between / Invert copied from SeriesChaptersSection.kt:262-272 — which is what the dialog finding above specifies. Nothing to change on the web either.

### Offline UI is hidden entirely in a plain browser on web — INTENTIONAL
- **area:** Offline reading — Shiori web (A) vs Hub manga half (C1)
- **why it is correct:** No action. A browser tab has no persistent filesystem and no background downloader, so offline legitimately exists only on the native shells. Do NOT let the gap #1/#2 port leak offline UI into the plain-web build — keep the new reader branch behind the existing `isNative()` / `nativePrimitives() !== null` guard, and have the new offline-series route render the same "this lives in the app" notice pattern as app/downloads/page.tsx:57-67 when `!isNative`.

### Hub-only files have no place in the ledger, so each audit re-litigates them as drift
- **area:** No parity ledger for the Hub, and a live third fork feeding it — Shiori web (A) vs Hub manga half (C1)
- **why it is correct:** Add a second table to hub/docs/UI_PARITY.md headed "Platform-only — no web twin, do not port" listing these 13 files with a one-line reason each (GPU texture limit; D-pad focus; no keyboard on a TV; expect/actual seam), and amend the rule at :15-18 to "every WEB screen gets ported" so it stops reading as a prohibition on platform code. This is bookkeeping, not a code change — but without it every parity pass spends its budget re-deciding the same 13 files, which is exactly the cost this ledger is supposed to remove.
